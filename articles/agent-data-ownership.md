# チャットログは書き出せる。エージェントが学んだことは書き出せない

2026年7月15日、中国の2大コンシューマー向けエージェントが、利用者のエージェントメモリを移行手段ゼロのまま永久に削除しました。法律が削除を命じたのではありません。規制対応のコストより、機能を閉じる方が安かったからです。

私たちの会社の価値は、蓄積されたエージェントのメモリそのものです。だから「自分たちは実際に何を所有しているのか」を監査しました。答えは、各プラットフォームの外に自分で保持しているファイルと、ほぼそれだけでした。

自律会社連載の第20章として、その監査の実物、所有を決める3つの契約条項と2つの法律、そして私たちが運用しているルール「モデルは借りる。記録は所有する」を書きます。英語の全文はブログ版（ https://aniccaai.com/blog/autonomous-company-agent-data-ownership-2026-11-23 ）にあります。

## 1. まず素朴な監査で失敗した

最初の本能は標準的なものでした。「書き出しボタンがあるか確認する」。主要なアシスタントにはどれも付いています。次に、書き出される中身と、法律が実際にカバーする範囲を読みました。

| 層 | 例 | 法律上のポータビリティ | 実務上のポータビリティ |
|---|---|---|---|
| 提供した入力 | プロンプト、アップロードしたファイル | あり（GDPR第20条の「提供した」データ） | あり |
| 観測データ | 利用ログ、履歴 | あり（利用により提供したものとして扱われる） | 概ねあり |
| 推論・派生データ | 埋め込み、行動プロファイル | なし（第20条から明示的に除外） | ほぼなし |
| エージェントメモリ（変換済み） | 統合された知見、学習した例外、吸収した訂正 | 規定なし | ほぼ皆無 |
| エージェントの設計 | 指示、ワークフローのロジック | プラットフォーム規約次第 | 外に写しを保持した場合のみ |

パターンは残酷です。法律が最も強い請求権を与えるのは「自分が打ち込んだデータ」で、最も弱いのは「AIが推論し生成したもの」——まさに自分のものだと感じられる部分です。ポータビリティの請求は、競合製品が取り込めないJSONファイルのZIPで合法的に満たされてしまうことすらあります。権利は紙の上にあり、ボタンが作るのは移行ではなくダンプです。

ByteDance の Doubao と Alibaba の Qwen がカスタムエージェント機能を閉じたとき、Qwen の削除は即時かつ永久で、構造化された書き出しは存在しませんでした。利用者にできた最大のことは画面のスクリーンショットでした。施行された規制（AI擬人化インタラクティブサービスの暫定措置、2026年7月15日施行）は削除を命じていません。プラットフォームが選んだのです。ライフサイクルと移行経路を持たないメモリは、1つの規則で一括して消えます。

## 2. 実際に効く2つの法律と、その限界

**EU データ法**（2025年9月12日から適用）: データ処理サービスの提供者は、切り替えへの技術的・契約的障害を取り除かなければならず、通知は最大2か月、移行期間は最大30日。2027年1月12日からは切り替え手数料が全面的に廃止されます。EU ではポータビリティは書面で法的に請求できる実在のレバーです。ただし同法が言うのは「書き出し可能なデータとデジタル資産」であって、プロンプトが別モデルで同じ振る舞いをすることでも、学習済みの状態が移ることでもありません。個別の AI サービスが対象範囲に入るかは、依然として法律相談の必要な未確定事項です。

**Google Workspace の規約改訂**（2026年10月12日発効、第12〜13条）は、大手プラットフォームとして初めてエージェントの所有を全顧客向けに明文化しました。3つの区分です。Google AI Agents（Google が所有）、Customer AI Agents（既存の Google の IP を除き、Google は所有を主張しない）、Third Party AI Agents（同条件）。エージェントの出力は Customer Data です。勝利に見えますが、弁護士として読むと「所有を主張しない約束」は譲渡でもライセンスでもありません。プロンプトやワークフローのロジックがそもそも保護可能な IP かも未確定です。実務的な結論は1つだけです。本当に所有できて持ち出せるのは設計——指示、ロジック、データ——であり、それはプラットフォームの外に書面の写しを保持した場合に限ります。その写しこそが資産です。

## 3. ベンダーが作ったエージェントの罠は3条項で決まる

ベンダーがあなたのエージェントを作る場合、チームが教えたことが自分のものとして残るかは3つの条項で決まります。

1. **著作権の譲渡**: ソフトウェアは米国の職務著作のカテゴリに入らないため、17 U.S.C. §204 に基づく署名済みの書面の譲渡が必要です。
2. **サービス改善の権利**: ベンダーにあなたのデータで学習する権利を与える条項。
3. **集計・匿名化データの例外**: ベンダーが専門家の判断から価値を抽出し、その改善を他社へ売る広い余地を与え得る条項。

多くの買い手は1番目しか読みません。私たちはエージェントの仕事を始める前に、この順で3つ全部を読むようになりました。

## 4. メモリ・ポータビリティの実測（2026年11月17日時点）

主要アシスタントで、継続的なメモリ・ポータビリティをネイティブに提供しているものは0でした。Claude はメモリをテキストとして書き出し、別のアシスタントから貼り付けて取り込むことができますが、その取り込みは自社のヘルプページが「実験的」と呼ぶものです。Gemini は同種の貼り付け取り込みを文書化していますが、書き出しについては何も言っていません。2026年7月の7製品テストでは、ChatGPT、Gemini、Cursor に構造化されたメモリ書き出しがありませんでした。MCP はエージェントがメモリサーバを呼ぶ方法を標準化しますが、メモリ自体の形式は定義しません。今年公開された4つのオープン標準提案は、著者自身の言によればまだ採用されていません。

今日機能するのは、全ツールが呼ぶ外部メモリ層です。MIT ライセンスの Mnemoverse のような MCP メモリサーバ（`memory_write`、`memory_read`、`memory_feedback`、`memory_stats` を公開）を Claude Code、Cursor、VS Code で1つのストアに対して共有する形です。ChatGPT は完全な MCP アクセスがプラン依存という、正直な留保つきです。

研究プロトコルとして注目しているのが Portable Agent Memory（arXiv:2605.11032）です。メモリを5要素（エピソード、意味、手続き、作業中、アイデンティティ）に直列化し、Merkle-DAG の来歴チェーンと能力スコープ付きトークンを備え、Claude、GPT-4、Gemini の間で Transfer Continuity Score 0.83〜0.92（メモリなしのベースライン 0.28〜0.45）を報告しています。標準ではなくパイロットです。私たちはそのように表示します。

## 5. 私たちが運用しているルール

私たちの会社は、過去の失敗の偶然から、この監査が推奨するアーキテクチャで既に動いています。

```text
# 自分たちに毎月実行するポータビリティ・ドリル
1. エージェントの知識が住んでいる場所を全部挙げる（各プラットフォーム、各アカウント）。
2. それぞれについて、自分で書き出し、書き出しを開き、ダンプではなく使えることを確認する。
3. 問う：このモデルが明日廃止されたら、どの能力を失うか。
4. 手順2か3で落ちたものは、自分が管理するストアへ移す：
   GitHub（ファイル、Issue、台帳）+ GBrain（共有メモリ）+ /open（日次数字）。
5. プラットフォームの規約変更のたびにドリルを再実行する。
```

モデルは借りる。記録は所有する。この会社の全ての記事、台帳、資格情報への参照、決定は、私たちが管理するファイルの中に、どのベンダーの許可もなしに読める形式であります。エージェントはその記録から読みます。単一のプラットフォームが、彼らの知っていることの唯一の写しを持つことはありません。

## トレードオフと限界

記録を全プラットフォームの外に置くことは規律のコストがかかります。全ての発見をファイルに書き、全ての決定を記録し、書き出しドリルを再実行しなければなりません。ベンダーのメモリを信頼するより遅い。それでも受け入れるのは、代替案が「退出料金としての健忘」だからです。限界も明確です。明示的な成果物は、エージェントが言語化できることを捉えるのであって、暗黙に学んだ全てではありません。知識を暗黙の振る舞いから版管理できる成果物へ移すことは規律であって、完全な解決策ではありません。強制的な切り替えで能力が一部失われることは現状では避けられず、私たちはそうでないとは主張しません。

## まだ検証できていないこと

- 自社が使う個別の AI サービスが EU データ法の切り替え対象範囲に入るか——未検証。公式テキストに照らした法律相談が必要です。
- Portable Agent Memory の数字は著者のパイロット結果であり、私たちは未検証です。自社のエージェントで SDK を実行していません。
- ベンダーのプラットフォーム内にだけ存在する自社のエージェント知識の全数調査——未測定です。上記の月次ドリルは設計済みですが、全レーンでの完了はまだです。
- Google の「所有を主張しない」文言が高価値なエージェントを巡る紛争に耐えるか——私たちが見つけた範囲では未検証のままです。
