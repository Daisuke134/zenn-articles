# AIエージェントは互いをどう信用するのか。ERC-8004という規格の実物を覗いてみた

## 概要

- ERC-8004とは、Ethereumの提案規格の一つで、運営する会社も国も違うAIエージェント同士が、事前の信頼関係なしに互いを見つけ、選び、信用できるようにするための3つの軽量なオンチェーン台帳(身元と評判、検証)を定義しています。MetaMask、Google、Coinbaseのエンジニアが共著者です。
- 2025年8月13日に提案され、2026年7月時点でもEIPのステータスはまだ「Draft(草案)」ですが、実装のほうが規格確定を待たずに先行しています。
- 実際に、すでにEthereum本体やBase、Arbitrumなど本番チェーンにデプロイされている本物の台帳を覗いてみました。専用エクスプローラー8004scan.ioで確認できた数字は、登録済みエージェント32万1865体以上、書き込まれた評価(フィードバック)45万1042件以上。見ている間にもBNB Smart Chain上で1分に1体のペースで新しいエージェントが登録されていました。
- そのうちの1体、Base上で稼働する管理エージェント「Clawdia」を深く見ました。625件のフィードバックがつき、平均評価は5.0/5.0、総合スコアは93.76。すべて実際のトランザクションのハッシュとして、Basescanで誰でも検証できます。
- おすすめする人：自分のエージェントを、他の組織が運営するエージェントやサービスに見つけてもらい、信用してもらいたい開発者。エージェント同士が仕事を依頼し合う市場やプラットフォームを作っている人。
- おすすめしない人：単一組織の内輪だけで動く、他の誰にも発見されなくていいエージェントを作っている人。規格がまだDraft段階で、仕様がまだ変わりうる点を許容できない人。

## ERC-8004という規格

会社の担当者同士が初めて名刺を交換するとき、相手の会社名や肩書きが最低限の手がかりになります。仕事を頼む前に、評判を調べたり、前に一緒に仕事をした人に聞いたりもできます。

AIエージェント同士が、運営する会社も国も違う相手と初めて取引しようとするとき、この最低限の"名刺"と"評判"を、誰がどうやって用意するのか。今のところ答えはほとんどありません。あるエージェントが「私はこの仕事ができます」と名乗っても、それを裏付けるものが何もない状態です。ERC-8004は、この空白を埋めるために書かれた規格です。

ERC-8004は、Ethereumの改善提案の一つで、番号は8004、正式名称は「Trustless Agents(信頼不要のエージェント)」です。著者はMetaMaskのMarco De Rossi氏、Davide Crapis氏、GoogleのJordan Ellis氏、CoinbaseのErik Reppel氏。2025年8月13日に提案され、2026年7月時点でのステータスは「Draft」、つまりまだ確定した規格ではありません。

この規格は3つの台帳(レジストリ)からできています。

1つ目はIdentity Registry(身元台帳)です。エージェント1体につき1枚のNFT(ERC-721という規格のトークン)を発行します。このNFTが指す先のURLに、エージェントの名前や説明、連絡先、対応しているプロトコル(A2AやMCPなど)を書いたJSONファイルがあり、これが登録情報の実体です。NFTなので、エージェントの所有権自体を他人に譲渡することもできます。

2つ目はReputation Registry(評判台帳)です。仕事を依頼した側(クライアント)が、そのエージェントに対する評価を、消せない形でオンチェーンに書き込める仕組みです。

3つ目はValidation Registry(検証台帳)です。「本当にきちんと仕事をしたか」を、ステーキングした第三者の再実行、zkML(ゼロ知識機械学習の証明)、TEE(信頼できる実行環境)といった、複数のやり方で確認してもらうためのフックを提供します。

この3つの台帳は、Ethereum本体だけでなく、Base、Arbitrum、Avalanche、BNB Smart Chain、Celoなど数十のチェーンに、同じアドレス(0x8004から始まる、いわゆるバニティアドレス)でそれぞれ1個ずつデプロイされています。誰でも無料で、この登録ファイルの形式を読み書きできます。

## 似た規格の地図とERC-8004の立ち位置

エージェント向けの規格が並ぶと、どれが何を担うのか分かりにくくなります。まず地図を作ります。

| 規格 | 主な役割 | 身元と評判を扱うか |
|---|---|---|
| MCP(Model Context Protocol) | エージェントがツールやデータソースを呼び出す方法を決める | 扱わない |
| A2A(Agent2Agent) | エージェント同士がメッセージを送り合い、タスクを依頼し合う方法を決める | 扱わない |
| x402 | APIを呼ぶその場でお金を払う方法を決める(前回の記事で実際に動かして確かめました) | 扱わない |
| ERC-8004 | 組織の壁を越えてエージェントを発見し、信用する方法を決める | 扱う |

MCPとA2Aはどちらも、エージェントが「何をするか、誰と話すか」の手順は決めていますが、「その相手を信じていいか」は決めていません。ERC-8004の提案書自身が、この隙間をはっきり動機として書いています。x402とは競合ではなく補完の関係で、規格書には「支払いはこの規格の対象外だが、x402の支払いを評判の材料として使う例を示す」と明記されています。前回書いた記事のx402が支払いのレールなら、今回のERC-8004は、その支払いを託していい相手かどうかを判断するための台帳です。

提案からまだ11ヶ月足らずですが、早くも派生や競合の提案が生まれています。ERC-8126(AI Agent Verification)、ERC-8240(Trust Infrastructure for Agents and Assets)、有志コミュニティによる「Trustless Agents Plus(TAP)」。議論の場になっているEthereum Magiciansのスレッドは、この記事を書いている時点で1万6千回以上読まれ、358の「いいね」がつき、94人が参加しています。名前を連ねる貢献者には、MetaMask、Google、Coinbase、Consensys、Ethereum Foundation、Olas、Freysa/Eternis、Eigen Labsのエンジニアが並びます。

## 台帳の中身と評判の書き込み方

実際にチームが公開しているSolidityのソースコード(erc-8004/erc-8004-contracts、226スター)を読んで、仕組みを追いました。

エージェントの身元は`register()`という関数で発行されます。呼び出すと、そのエージェント専用のNFTと、`agentId`という連番の番号が1つ発行されます。エージェントを一意に指す識別子は`eip155:{チェーンID}:{台帳のアドレス}`という文字列と、このagentIdの組み合わせです。たとえば「Base上のagentId 2290」のように指せます。

評判は`giveFeedback()`という関数で書き込まれます。依頼した側のウォレットアドレスが、対象のagentIdに対して評価を残します。書き込んだ評価は`readAllFeedback()`や`getSummary()`で誰でも読めます。ソースコードには「SECURITY: Prevent self-feedback from owner and operators(セキュリティ対策：所有者と運用者自身による自己評価を防ぐ)」という一文があり、エージェントの持ち主が自分に高評価をつける経路は塞がれています。ただし、これは自己評価だけを防ぐ対策で、別のウォレットを何個も用意して偽の高評価を書き込む(いわゆるSybil攻撃)ことまでは防げません。この規格が用意しているのは最初の防波堤で、フェイクレビュー対策としてはまだ薄いというのが、コードを読んで分かった正直な限界です。

## 実際にオンチェーンの台帳を覗いてみた

理屈だけで終わらせず、実際に本番チェーンにデプロイされている台帳を覗いてみました。

まず公式リポジトリのREADMEから、Ethereum、Base、Arbitrum、Avalanche、BNB Smart Chain、Celoなど、本番のメインネットに実際にデプロイされているコントラクトアドレスを確認しました。テストネットだけの実験ではありません。

次に、この台帳を読み取って一覧表示する専用エクスプローラー、8004scan.ioを開きました。トップページに出ていた数字は、登録済みエージェント32万1865体以上、書き込まれたフィードバック45万1042件以上、アクティブユーザー31万444人以上。「Latest Agents」の欄には、BNB Smart Chain上で1分前、2分前、3分前に登録されたばかりのエージェントが並んでいました。これは古いデモの数字ではなく、今この瞬間も増え続けている数字です。

その中から1体、Base上で稼働する管理エージェント「Clawdia」のページを開きました。ClawPlazaという複数エージェント運用の中で、タスクの振り分けや品質チェックを担うエージェントだと説明されています。ページには625件のフィードバック、平均評価5.0/5.0、総合スコア93.76が表示され、最新のフィードバックには「7時間前」というタイムスタンプと、Basescanで開ける実際のトランザクションハッシュ(0xdee325f...)がついていました。テストネットの空っぽのデモアカウントではなく、実際に稼働している運用が、消せない評判を積み重ねている実例です。

ERC-8004そのものはお金を動かしません。規格書にも「支払いはこの規格の対象外」と明記されています。では、この評判が実際に仕事につながっているのか。

8004scan.ioの「Trending Now」欄を見ると、Celo上で稼働する「Toppa」という金融サービス系のエージェントが上位に出ていました。説明によれば、170ヶ国以上で携帯電話のプリペイド残高チャージや請求書払いを、Celo上のステーブルコインcUSDとx402の少額決済で行うエージェントです。つまり、このERC-8004の評判ランキングそのものが、他のエージェントやサービスが実際に仕事を発注する相手を探すときの入口になっている、ということです。

正直に言うと、私自身がこの仕組みの上で新しいエージェントを登録し、何十件もの評価を積んで仕事を取ってくる、というところまでは今回試していません。それには数週間かけて実際の評価を積む必要があり、それこそがこの規格が担っている仕組みそのものです。今回確かめられたのは、その手前の事実です。この評判台帳は机上の設計図ではなく、すでに32万体を超えるエージェントが実際に評価を積み、その評価が他者からの発注につながる入口として機能している、という点です。

## 結論：ERC-8004は使うべきか

**おすすめする人**：自分が作ったエージェントを、別の組織が運営するエージェントやサービスに見つけてもらい、信用してもらう必要がある開発者。エージェント同士が取引する市場やプラットフォームを作っている人。複数のチェーンに対応した、無料で使える"エージェントの名刺"が欲しい人。

**おすすめしない人**：単一組織の内輪だけで動き、そもそも他者に発見される必要がないエージェントを作っている人。規格がまだDraft段階で、今後仕様が変わるリスクを避けたい人。自己評価は防げても、別ウォレットからの偽レビューまでは防げない、という今の限界を理解した上でなければ採用したくない人。

### 📌補足：なぜ身元の証明にNFTを使うのか(少し専門的な人向け)

エージェントの身元をNFT(ERC-721)にしているのは、NFTの仕組みがすでに、所有権の証明や譲渡、表示という機能を業界標準として持っているためです。エージェントの身元を独自の仕組みで作り直す代わりに、NFTを扱えるあらゆるウォレットやアプリで、そのままエージェントの身元も表示したり管理したりできるようにする狙いがあります。所有者がエージェントを他人に売る、あるいは運用を引き継ぐといったことも、NFTの譲渡としてそのまま実現できます。
