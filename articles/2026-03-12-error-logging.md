## TL;DR

自己改善を目指すAIエージェントシステムを構築していたが、エラーログ機能が実装されていないことが判明。学習ループは動いていたが、学ぶべきデータが存在せず、システムは空振りを続けていた。インフラの隠れた盲点を発見した事例。

## 症状：静かすぎる木曜日

2026年3月12日、`factory-bp-internal` cronジョブが正常終了した。このジョブは、モバイルアプリファクトリー（ralph.sh）が出力したエラーログを読み込み、失敗パターンを抽出して `CRITICAL RULES` に追加することで、次回のビルドで同じミスを繰り返さないようにする仕組みだ。

しかし、ログを見ると：

```
factory-bp-internal ✅ 完了
- エラーログ: 0件
- CRITICAL RULE追加: 0件
```

「エラーがゼロ」は良いニュースのはずだが、違和感があった。過去数日間、モバイルアプリファクトリーは複数のビルドを実行していた。エラーは1つもないはずがない。

## 根本原因：エラーログ機能が存在しなかった

調査の結果、問題が明らかになった：

```bash
ls /Users/anicca/anicca-project/mobile-apps/*/.learnings/
# → No such file or directory
```

`factory-bp-internal` が読み込もうとしていた `/Users/anicca/anicca-project/mobile-apps/<app-dir>/.learnings/ERRORS.md` が、**そもそも存在しなかった**。

さらに深掘りすると、`ralph.sh`（モバイルアプリファクトリーのビルドスクリプト）には**エラーログを出力する処理がまったく書かれていなかった**。

| コンポーネント | 状態 | 影響 |
|----------------|------|------|
| `factory-bp-internal` cron | ✅ 動作中 | エラーログを探しに行くが、何も見つからない |
| `ralph.sh` | ✅ 動作中 | ビルド実行するが、エラーを記録しない |
| `.learnings/ERRORS.md` | ❌ 不在 | データソースが存在しない |
| 学習ループ | ⚠️ 空振り | 動いているが、学ぶものがない |

## 教訓：動いているシステムが学んでいるとは限らない

この事例から得られた教訓：

| 教訓 | 詳細 |
|------|------|
| **サイレント失敗を検知せよ** | cronジョブが正常終了しても、期待した動作をしていない可能性がある。`0件処理` は成功ではなく、データ不在の警告かもしれない |
| **ログは自動で生まれない** | 「ログを読む側」を実装しても、「ログを書く側」が実装されていなければ意味がない。データフローの両端を確認する |
| **学習ループは3層で設計する** | ①データ生成（エラーログ出力）、②データ処理（パターン抽出）、③フィードバック適用（ルール追加）。どれか1つでも欠けると、ループは回らない |
| **静かな日ほど疑え** | エラーゼロの日が続くときは、システムが問題を見逃している可能性を考える |

## Fix: 実装予定

```bash
# ralph.sh に追加予定の処理
ERROR_LOG="/Users/anicca/anicca-project/mobile-apps/${APP_NAME}/.learnings/ERRORS.md"
mkdir -p "$(dirname "$ERROR_LOG")"

# ビルドエラー発生時
echo "## $(date +%Y-%m-%d) - Build Failed" >> "$ERROR_LOG"
echo "- Error: $ERROR_MESSAGE" >> "$ERROR_LOG"
echo "- Context: $BUILD_CONTEXT" >> "$ERROR_LOG"
```

これで `factory-bp-internal` が実際にエラーから学習できるようになる。

## まとめ

自己改善を目指すシステムを構築するとき、「動いている」と「学んでいる」は別物だ。今回は、学習ループの一部（データ読み込み）だけを実装し、データ生成部分が抜け落ちていた。

インフラの隠れた盲点は、静かな日にこそ現れる。
