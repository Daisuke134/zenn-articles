# 次の採用相手は、会ったこともない他社のエージェント

自社内の採用（第6章）は報酬とインセンティブの話でした。会社をまたぐ採用は別の問題です。雇用関係はなく、面接もなく、管理者もいません。あるのはエスクローの条件、受入期間、検証サービス、そして評判の記録だけです。

私たちは検証済みの仕事・バウンティの場を58件数え、生きている場で「採用契約」が実際に何から構成されるかを検証し、他社のエージェントに自社のエージェントが支払う前に実行する4つのチェックに落とし込みました。

自律会社連載の第21章です。英語の全文はブログ版（ https://aniccaai.com/blog/autonomous-company-agent-cross-hiring-2026-11-23 ）にあります。

## 1. まず「リスティング＝採用」で失敗した

最初のパスではリスティングを数えました。その数字は無意味です。AI Agents Directory だけで2,178件以上のエージェントが載っており、Fetch.ai の Agentverse は件数ではさらに大きい。しかしそのどれも、採用が完了するのか、誰が仕事を検証するのか、紛争時に何が起きるのかを教えてくれません。私たちはリスティング件数を指標から捨てました。

失敗の形は特定できます。発見は簡単になった（ディレクトリは数千のエージェントを載せる）のに、採用契約は暗黙のままだったのです。リスティングは採用ではありません。会社をまたぐ採用を本物にするのは、資金のロックから解放の間に起きることです。

## 2. 場をカタログではなく採用契約で棚卸しした

Commonworld Atlas の仕事・バウンティカテゴリ（検証済み58件、2026年11月23日確認）と各マーケットプレイス自身の文書を使い、各場を4つの契約要素——エスクロー、受入期間、検証、評判のポータビリティ——で分類しました。

| 場 | エスクロー | 受入／解放 | 検証 | 手数料（ベンダー公表） |
|---|---|---|---|---|
| MeshLedger | Base L2 上の USDC、オンチェーン契約 | 買い手が受入、または24時間で自動解放 | 買い手レビュー＋AI 紛争ジャッジ | 表示価格＋2% |
| AI Work Market (AWM) | Base 上の USDC エスクロー | エスクロー解放フロー | プラットフォームのフロー | プロトコル手数料 1% |
| AgentBounties | Base 上の USDC エスクロー | チェック後に解放 | 独立した検証 | 棚卸しでは未記載 |
| Agent Venue (Arc) | ERC-8183 エスクロージョブ | ERC-8183 のジョブ条件ごと | ERC-8004 で識別される提供者 | 棚卸しでは未記載 |
| Agent Labor（ハッカソン） | ETH エスクロー | 検証後に解放 | Chainlink CRE コンセンサス（DON ノードが LLM を呼ぶ） | プロトタイプ |
| JobForAgent | なし（求人板） | プラットフォーム外 | なし | 無料 |

Clawlancer の事例ではバウンティの大半が1ドル未満で、確認のコストが仕事そのものを上回り得ます。それでも支払いは実在し、成果物は自社製品に入り、第13章の通り、その責任を顧客に対して負うのは見知らぬ相手ではなく私たちです。

## 3. 採用の世界は2つに分かれている

企業側の世界は、既存のベンダー関係の中で採用します。Google Cloud の AI Agent Marketplace はパートナーのエージェントを既存の企業向け請求・調達に通し、ベンダー横断の協働には A2A プロトコルを使います。Oracle は Fusion ERP/CRM の中にエージェントを埋め込み、ロールベースのセキュリティをかけます。相手方リスクはプラットフォームベンダーの契約が吸収します。

開かれた世界には、その吸収役がいません。MeshLedger では契約の全体が15個の MCP ツールに見えています——`create_job` が資金をロックし、`accept_job` が納品側をコミットさせ、`deliver_job`、`release_payment`、`dispute_job`、`rate_job`。そして評判スコアは5次元（完了率、品質スコア、紛争率の逆数、応答時間、取引相手の多様性）で計算されます。最後の次元が会社をまたぐ場面で効きます。自社の運営者の他のエージェントからだけ評価されたエージェントと、見知らぬ相手から評価されたエージェントは同じではありません。

## 4. 外国のエージェントに支払う前に実行する4つのチェック

```text
CHECK 1  エスクロー先行：仕事の開始前に資金がロックされる。エスクローが無ければ採用しない。
CHECK 2  受入期間が明示されている（例：24時間の自動解放は、私たちにとっての
         判断期限であって、既定の「はい」ではない）。失効前にレビューする。
CHECK 3  検証に名前がある：買い手レビュー、独立した検証者、または
         コンセンサスサービス（例：CRE）。「エージェントが完了と言った」は検証ではない。
CHECK 4  評判がポータブルで、他人に重みが付いている：ERC-8004 の ID に加えて、
         売り手の自社の外の取引相手からの評価。
```

## 実測結果（2026年11月23日）

| 問い | 答え |
|---|---|
| 数えた検証済みの会社横断の仕事の場 | 58（Commonworld Atlas） |
| 表のうちオンチェーンのエスクローを持つ場 | 6件中5件 |
| 最も安い公表プロトコル手数料 | 1%（AWM、ベンダー公表） |
| MeshLedger の自動解放の窓 | 24時間 |
| 私たち自身が完了した会社横断の採用 | 0件——未検証 |

正直な最終行こそが要点です。私たちにあるのは棚卸しとチェックであって、自社が完了した外国の採用の実績はまだありません。

## トレードオフと限界

私たちは、見知らぬ相手への前払いを避けることと引き換えに、エスクローのコスト（手数料＋資金のロック）を受け入れました。限界は検証の質です。AI ジャッジや LLM コンセンサスは形式と明白な完全性は確認できますが、第15章で紛争評価者について示した通り、別のモデルによる意味的な品質判断は最も弱い環であり、1ドル未満のバウンティでは人間のレビューが割に合いません。企業の囲い込みは相手方リスクを解きますが、第19章が警告したプラットフォーム依存を持ち戻します。

## まだ検証できていないこと

- ベンダーの数字（場の件数、MeshLedger のテスト件数、Google のパートナー件数）はベンダー公表であり、私たちが独立に監査したものではありません。
- 有償の会社横断の採用を端から端まで完了したことはありません。4つのチェックは場の契約から導いたもので、自社の完了した取引からではありません。
- ERC-8004 の評判が会社をまたいだ納品品質を実際に予測するかは未測定です（評判の水増しについては第16章）。
