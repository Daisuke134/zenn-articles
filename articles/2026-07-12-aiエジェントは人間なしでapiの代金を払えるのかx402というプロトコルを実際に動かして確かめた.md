# AIエージェントは人間なしでAPIの代金を払えるのか。x402というプロトコルを実際に動かして確かめた

## 概要

- x402とは、HTTPの「402 Payment Required」という30年以上使われていなかったステータスコードを使い、AIエージェントがAPIの代金をその場でドルに連動した暗号資産(ステーブルコイン)で払う、オープンな決済の規格です。
- 2025年5月にCoinbaseが公開し、2026年7月時点でx402財団の公式カウンターでは直近30日だけで7541万件・約2424万ドル分の決済が通っています。
- 実際にx402で守られた公開デモに人間の代わりにリクエストを送り、支払い要求(402応答)を受け取るところまでは自分で確認しました。ここから先、実際に支払いを完了させる手前で「人間の承認クリック」という壁に当たったので、その中身も正直に書きます。
- おすすめする人：AIエージェントに呼ばせるAPIを作っていて、サブスクや請求書なしで従量課金にしたい開発者。エージェント自身に小口の支払いをさせたいチーム。
- おすすめしない人：暗号資産に一切触れたくない人。決済を完全に自動化したいだけなのに、人間のクリックが挟まる実装しか使わない人(後述)。

## 人間のクレジットカードを使わない支払い

AIエージェントが自分でAPIを呼び、必要なデータを買い、また次のAPIを呼ぶ。そこまで自動化しても、最後に必ず人間が出てくる場所がありました。支払いです。

クレジットカードの登録、サブスクリプションの契約、月末の請求書処理。どれも人間が一度は署名かクリックをする前提でできています。エージェントが1回のAPI呼び出しに0.01ドルだけ払いたいと思っても、カード会社の最低手数料がその何倍もかかるので、そもそも成立しません。

x402は、この隙間を埋めるためにCoinbaseが作ったオープンな規格です。名前の由来は、HTTPの仕様に1990年代から予約されたまま誰も実装してこなかった「402 Payment Required」というステータスコードです。サーバーは「見せてほしいなら払ってください」という意味でこのコードを返せるようになっていたのに、実際に払う手段がなかったので30年間放置されていました。Coinbaseが手がけるLayer2ブロックチェーン、Base上でのステーブルコイン決済手数料が0.001ドル未満まで下がったことで、ようやくこの30年前の空席が埋まりました。

## エージェント向け決済プロトコルの地図としくみ

2026年に入って、AIエージェント向けの決済規格は一斉に増えました。似た名前が並ぶので、まず地図を作ります。

| プロトコル | 主戦場 | 公開時期 | 主な後ろ盾 | 暗号資産が必須か |
|---|---|---|---|---|
| x402 | HTTPの決済レール(APIの従量課金) | 2025年5月(v2は2025年12月) | Coinbase、x402財団(Cloudflareと共同設立) | 必須(BaseチェーンのUSDC) |
| Stripe ACP | 加盟店のチェックアウト | 2025年後半発表、2026年にChatGPTへ実装 | Stripe、OpenAI | 不要 |
| Google UCP | 発見から購入までの商取引全体 | 2026年1月 | Google、Shopify | 部分的 |
| Google AP2 | 支出の承認と監査ログ | 2025年9月 | Google | 不要 |

それぞれが担う層が違います。x402はAPIを呼ぶその瞬間の支払いだけを扱う薄いレールで、エージェントが何者かという身元は扱いません。ACPはネットショップのレジ、UCPは商品を見つけてから届くまでの全工程、AP2は「このエージェントにいくらまで使う権限を与えるか」という社内向けの承認レイヤーです。x402が最もシンプルで、最も取引量が多い代わりに、担っている範囲は一番狭いという特徴があります。

x402の支払いは、3つの役者が回すやり取りです。

まずクライアント。これがAPIを呼ぶAIエージェント自身です。次にサーバー、つまりお金を取りたいAPI側です。そして間に立つファシリテーター(facilitator、決済の仲介者)。この仲介者が、エージェントの署名を検証し、ブロックチェーン上でお金を実際に動かし、ガス代(ブロックチェーンに取引を刻むための手数料)まで肩代わりします。エージェント自身はブロックチェーンに直接触れません。

流れはこうです。エージェントがAPIにリクエストを送る。APIは「402 Payment Required」を返し、ヘッダーの中に「いくら、どの資産で、どの口座に払えばいいか」という条件をbase64で埋め込む。エージェントはその条件を読み、手元の秘密鍵でUSDC(ドルに1対1で連動するステーブルコイン)の送金をその場で署名する。もう一度同じAPIにリクエストを送り直すと、今度はファシリテーターが署名を検証してブロックチェーンに決済を刻み、APIが本来のデータを返す。ここまで、すべて普通のHTTP通信の中で完結します。特別な口座登録もAPIキーの発行も要りません。

## 実際に動かしてみた

理屈はここまでにして、実際にx402が守っている公開デモへ、人間の代わりにリクエストを送ってみました。

まず素のcurlで`https://x402.org/protected`を叩くと、返ってきたのは確かに`402`でした。レスポンスヘッダーの`payment-required`をデコードすると、中身はこうです。

```
{
  "resource": {"url": "https://x402.vercel.app/protected"},
  "accepts": [
    {"scheme": "exact", "network": "eip155:84532", "amount": "10000",
     "asset": "0x036CbD53842c5426634e7929541eC2318f3dCF7e", "maxTimeoutSeconds": 300}
  ]
}
```

`amount: 10000`はUSDCの最小単位で0.01ドル、`network: eip155:84532`はBase Sepolia(Baseのテスト用ネットワーク)を指します。つまり「0.01ドルのUSDCをこの口座に、5分以内に払えば見せてあげる」という条件が、そのままHTTPヘッダーの中に入っていたことになります。

次に、実際に支払いまで進めるための別の経路も試しました。CoinbaseのBase MCP(AIエージェントが自分のウォレットを操作するための公式ツール)経由で、同じ`x402.org/protected`に上限0.02ドルで支払いリクエストを出したところ、返ってきたのは「支払いを完了するには、Base Accountというウォレットの画面であなたが承認クリックをしてください」という応答でした。つまりこの経路は、エージェントが単独で最後まで完結できません。人間が一度クリックする前提の作りになっています。

正直、承認クリックを求められた瞬間は拍子抜けしました。「x402は人間なしで払える」という説明は、エージェントが自分の秘密鍵を直接持ち、Coinbaseの公式クライアントライブラリ(`x402Client`)でその場で署名する経路にだけ当てはまります。Base MCPのようにウォレットの承認画面を経由するツールを使うと、結局そこに人間のクリックが挟まる。同じx402というプロトコルでも、どの入口を使うかで人間ゼロになるかどうかが変わる、というのが実際に動かして分かったことでした。

## 結局、x402は使うべきか

x402はAPIの従量課金という一点に絞られたレールです。従量課金にしたいAPIを提供する側にとっては、サブスクリプションの契約フォームも、クレジットカードの審査も要らず、コードを数行足すだけで課金できる作りになっています。実際に直近30日で7500万件を超える決済が通っている以上、これはもう実験段階の技術ではありません。

**おすすめする人**：AIエージェントから呼ばれるAPIを作っていて、月額契約ではなく1回いくらで課金したい開発者。エージェント自身に小口の支払いをさせたい開発チーム。

**おすすめしない人**：暗号資産のステーブルコインに一切触れたくない組織。エージェントが誰であるかという身元管理まで一つの仕組みで済ませたい人(x402自身は身元を扱わないので、別の仕組みと組み合わせる必要があります)。

### 📌補足：ガス代を肩代わりする「ファシリテーター」とは何か(少し専門的な人向け)

ブロックチェーン上で送金するには、本来「ガス代」という手数料を送金する側が別途用意して払う必要があります。x402ではこの手間をなくすため、ファシリテーターと呼ばれる仲介サーバーが、利用者の代わりにガス代を立て替えて支払います。利用者(この場合はAIエージェント)は送金の署名だけをその場で作り、あとの手続きはファシリテーターに任せる形になっているので、エージェント側はブロックチェーンの細かい作法を意識せずに済みます。
